# UC-06 assumptions register

Every invented shape or behaviour in this build, with the reason, the risk, and
where it lives in code. **Nothing here is confirmed by the company.** Each row is
a question for the company, not a decision we have made on their behalf.

The upstream systems UC-06 depends on have not been delivered: no API
specifications, no endpoints, no sample payloads. So the contracts below were
defined by us, mocked, and built against. When the real systems arrive, check
these rows **before** writing an adapter — `docs/INTEGRATION.md` names which rows
apply to which dependency.

---

## A-01 — DISCLAIMER TEXT DISCREPANCY (read this first)

> **The scope document states the disclaimer twice, with different wording.**
> This is unresolved and requires the company's written confirmation before
> release. We picked one; picking one is not the same as it being right.

| | |
|---|---|
| **ID** | A-01 |
| **Area** | Disclaimer — canonical text |
| **Assumption** | The Overview's **three-sentence** text is canonical: *"This response is provided for educational and training purposes only. It does not constitute legal advice. Always consult a qualified legal professional before acting on any legal matter."* UC-06's own step 5 quotes a **shortened two-sentence** form, omitting the final sentence. We use the Overview's full text everywhere. |
| **Why** | The Overview declares the platform-wide canonical text; a step-level quotation is more likely to be an abbreviation than a second specification. We were also instructed to prefer the Overview. |
| **Risk if wrong** | Severe and automated. The specification calls this string non-negotiable and verifies it by automated scan. If the company confirms the shortened form, **every response this service has ever emitted carries the wrong disclaimer**, and the compliance scan either fails everywhere or — worse — was written against the wrong string and passes while the product is non-compliant. It is one constant to change; the exposure is every response already sent. |
| **Where in code** | `uc06/domain/disclaimer.py` — `CANONICAL_DISCLAIMER` (the single definition). The shortened variant is held as `KNOWN_VARIANT_UC06_STEP5` **only** so the boundary check can name the drift precisely; it is never emitted, and a payload carrying it is refused (`uc06/application/boundary.py`, `REASON_SHORTENED_VARIANT`). |
| **Tests** | `tests/test_disclaimer_layers.py::TestLayerOneTypeLevel::test_canonical_text_is_the_expected_string`, `::test_the_constant_is_defined_exactly_once_in_source`, `TestLayerTwoBoundaryCheck::test_the_uc06_step5_shortened_variant_is_refused_and_named` |
| **What we need** | One line from the company: which wording is canonical. Changing it is a one-constant edit; the cost is entirely in what has already been emitted. |

## Confidentiality decision (not an assumption — a decision the company owes us)

Enabling a real model provider transmits confidential and potentially privileged
case content to a third party. `ConfiguredAnswerGenerator` **refuses to
construct** until a constant in its own source file is changed, so this cannot
happen through configuration alone. The exact field list and the questions
requiring sign-off are in `docs/INTEGRATION.md` and in the module docstring of
`uc06/adapters/real/configured_generator.py`.
