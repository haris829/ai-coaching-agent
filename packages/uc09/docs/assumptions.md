# Assumptions register — UC-09 Session Summary & Export

Every field name, response shape, enum value, threshold and behaviour in this
component that the company has **not** specified is recorded here.

The register exists because this component was built against upstream systems
that do not yet exist. Each row is something an integration engineer must
confirm against the real system before the corresponding adapter is written.
Rows marked **HIGH** risk affect the truthfulness of a document a solicitor may
present to a regulator.

Items the company *did* specify — the NARIC enum and its members, the source
status vocabulary, the explanation profile bands for levels 3/5/7, the integer
0–100 completion percentage, the summary record field list, the four section
names, the `generated` / `question_log_fallback` generation modes, the
`summary_generated` session status, the lowercase-value rule, the port list,
and the API paths — are **not** listed here. They are documented as specified
in `SHARED_CONTRACT.md`.

## How to use this register

Before writing a real adapter, read the rows for that dependency (they are
listed per-dependency in `INTEGRATION.md`) and confirm each against the real
system. Where an assumption is wrong and the real payload cannot be mapped onto
the platform contract, raise it as a **contract conversation** — do not bend the
domain model inside an adapter.
