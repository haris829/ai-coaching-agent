# UC-03 — Shared contract

For an integration engineer who has not read this code and is holding a
component UC-03 has never seen. Every field below is marked:

- **[SPECIFIED]** — given by the company brief or the platform contract.
- **[ASSUMED]** — chosen by UC-03; see [assumptions.md](assumptions.md) for the
  reasoning and the risk. Assumed items are the negotiable ones.

UC-03 is a backend use case. It answers legal-learning questions, records every
interaction, and performs follow-up re-explanations. It owns no UI and no
database.

---

## 1. The interaction log record

**UC-03 is the only writer of this record.** Nothing else in the platform
should write rows to this stream. Readers are free.

One record is written per incoming interaction — answers, clarification
requests, out-of-scope redirects, errors, timeouts, unauthorised attempts, and
oversized input alike. Exactly one, on every path.

| Field | Type | Null? | Status | Meaning |
|---|---|---|---|---|
| `question_id` | `string` (UUID4) | no | [SPECIFIED] | Identity of this interaction. Generated by UC-03. |
| `session_id` | `string` | no | [SPECIFIED] | The session this belongs to. **Received, never created** — see §6. |
| `user_id` | `string` | no | [SPECIFIED] | Authenticated caller, resolved server-side from the credential. Never taken from a request body. |
| `question` | `string` | no | [SPECIFIED] | The learner's question verbatim (truncated to the input limit on the oversized-input path). |
| `classification` | `LEGAL_CONCEPT` \| `PROCESS` \| `DEFINITIONAL` \| `AMBIGUOUS` \| `OUT_OF_SCOPE` | yes | [SPECIFIED] values, [ASSUMED] casing (A-20) | Null when the request failed before classification. |
| `status` | see §7 | no | [SPECIFIED] + `FRAMINGS_EXHAUSTED` [ASSUMED] (A-14) | Outcome. |
| `answer` | four-part object (§3) | yes | [SPECIFIED] | **Null whenever no answer exists.** Never a placeholder. `status` says why. |
| `topic_tag` | closed enum (§2) | no | [SPECIFIED] concept, [ASSUMED] vocabulary (A-01) | Always a vocabulary member; `unclassified` when unknown. |
| `topic_tag_accepted` | `boolean` | no | [ASSUMED] | False when the tagger proposed nothing or proposed something outside the vocabulary. |
| `timestamp` | ISO-8601 datetime, UTC | no | [SPECIFIED] | From an injected clock. |
| `rating_state` | `pending` \| `rated` | no | [SPECIFIED] | **UC-03 only ever writes `pending`.** UC-10 owns the transition to `rated`. UC-03 never reads or updates it. |
| `naric_level` | `LEVEL_3`…`LEVEL_7_PLUS` | yes | [SPECIFIED] | The qualification level this answer was pitched at. Null before context resolution. |
| `naric_level_source` | `retrieved` \| `default` | yes | [SPECIFIED] | Whether that level came from the context service or was defaulted. **A level alone is never ambiguous because of this field.** |
| `concept_key` | `string` | yes | [ASSUMED] (A-13) | Concept identity, for the never-repeat-a-framing rule. |
| `framing` | closed enum (§8) | yes | [ASSUMED] (A-09) | Which explanation framing was used. |
| `follow_up_of` | `string` (UUID4) | yes | [SPECIFIED] | The `question_id` this interaction elaborates on. Null for an original question. |
| `follow_up_action` | `EXPLAIN_DIFFERENTLY` \| `ANOTHER_EXAMPLE` \| `GO_DEEPER` | yes | [SPECIFIED] | Null for an original question. |
| `elapsed_ms` | `integer` | no | [ASSUMED] | Server-measured wall-clock for the interaction. |
| `citation_guard_violations` | `integer` | no | [ASSUMED] | Count of citation-shaped fragments redacted from generated prose. **Non-zero means the generator tried to cite something unverified.** Worth alerting on. |
| `degraded` | `string[]` | no | [ASSUMED] (A-19) | Which dependencies were degraded. Empty on a clean path. |
| `error` | `string` | yes | [ASSUMED] | Machine-readable reason: `unauthorized_session`, `input_too_long`, `input_too_short`, `pipeline_error`. |

Write semantics: `log(record)` returns nothing and **reports failure by
raising**. A logging failure degrades the service (`meta.log_status = FAILED`,
`degraded` gains `question_log_unavailable`) but never fails the learner's
request; the record is written to stderr as a fallback so it is not lost.

## 2. Topic vocabulary — complete

Lowercase, closed. **[ASSUMED]** except `unclassified`, which is [SPECIFIED].

```
contract_formation      contract_remedies       negligence
criminal_liability      criminal_procedure      civil_procedure
land_and_property       employment              company_and_insolvency
family                  immigration             wills_and_probate
evidence                human_rights            legal_system
professional_conduct    unclassified
```

A tagger *proposes*; UC-03 *validates*. Any proposal outside this set is coerced
to `unclassified` and `topic_tag_accepted` is set false. An LLM tagger therefore
cannot invent a new analytics dimension.

## 3. The four-part response

**[SPECIFIED].** Four separate fields, never one blob — the frontend renders
each as its own section.

```jsonc
{
  "plain_english":     "string",   // adapted to the learner's explanation depth
  "formal_definition": "string",
  "practice_example":  "string",   // personalised to practice area when available
  "authority": {
    "status": "verified" | "no_verified_authority",
    "authority": {                 // present only when VERIFIED
      "citation":        "string",
      "title":           "string",
      "source":          "string",
      "url":             "string | null",
      "verified_by":     "string", // which system vouched for this
      "verification_id": "string", // traceable reference
      "retrieved_at":    "datetime"
    },
    "message": "string | null",            // present when NO_VERIFIED_AUTHORITY
    "verification_routes": ["Westlaw", "BAILII"]
  }
}
```

**Authority integrity — three independent defences.** Read this before
replacing the generator:

1. **Structural.** The generator contract (`GeneratedProse`) has only the three
   prose fields. A model is *incapable* of supplying the authority part.
2. **Provenance.** Only a `LegalAuthorityProvider` can produce `VERIFIED`, and
   it must fill `verified_by` and `verification_id`.
3. **Guard.** Generated prose is scanned for citation-shaped text — neutral
   citations, case names, named statutes, section/article references, EU
   instruments, URLs — and anything not exactly matching a verified citation is
   redacted and counted.

When no verified authority exists, the response says so and directs the learner
to **Westlaw or BAILII**. It never guesses.

## 4. Context UC-03 expects to receive

UC-03 does **not** talk to the context service directly. It calls a
`ContextProvider` adapter, which is expected to sit in front of the company
NARIC/qualification service and Legal Footprints.

```jsonc
{
  "user_id":                    "string",       // [SPECIFIED] echoed back
  "session_id":                 "string",       // [SPECIFIED] echoed back
  "naric_level":                "LEVEL_3|LEVEL_4|LEVEL_5|LEVEL_6|LEVEL_7|LEVEL_7_PLUS",
  "naric_level_source":         "retrieved|default",
  "practice_area":              "string | null", // [ASSUMED] free text, from Legal Footprints
  "practice_area_availability": "PROVIDED|MISSING|PROVIDER_UNAVAILABLE"  // [ASSUMED] A-18
}
```

Rules the adapter must honour:

- **Never invent a level or a speciality.** If it is unknown, say so via the
  source/availability field. The level itself always carries a real level, so
  `naric_level_source` is the only thing that distinguishes retrieved from
  defaulted.
- Raising is acceptable. UC-03 degrades to `LEVEL_3` / `default` /
  `PROVIDER_UNAVAILABLE` and records `context_provider_unavailable`.
- A level outside the closed set is coerced to the default and recorded as
  `naric_level_unrecognised`. It does not crash the request, but it is an
  adapter bug.

Where it comes from: **the company NARIC/context service and Legal Footprints.**
UC-03 does not know their shapes and does not import them — normalise inside the
adapter rather than widening this contract.

## 5. Explanation depth mapping

**[ASSUMED]** grouping (A-07). Pure function; no randomness anywhere.

| NARIC level | Depth | Register |
|---|---|---|
| `LEVEL_3`, `LEVEL_4` | `FOUNDATION` | everyday language, technical terms glossed, ≤4 sentences |
| `LEVEL_5`, `LEVEL_6` | `INTERMEDIATE` | undergraduate, specialist terms glossed, ≤5 sentences |
| `LEVEL_7`, `LEVEL_7_PLUS` | `ADVANCED` | practitioner, technical vocabulary unglossed, ≤3 sentences |

Default when no level was retrieved: `LEVEL_3` → `FOUNDATION`. The most
accessible register, so an unknown learner is never assumed to be an expert.

`GO_DEEPER` moves one step down the ladder
(`FOUNDATION → INTERMEDIATE → ADVANCED`); at `ADVANCED` the depth stays put and
only the framing changes.

## 6. Session identity — explicit confirmation

**UC-03 receives a session identifier. It never creates one on a production
path.**

- `session_id` arrives in the request body on every call.
- The authenticated `user_id` comes from the `Authorization` header only.
- Before anything else, UC-03 asks the `SessionAuthorizer` whether that user
  owns that session. If not: `403`, and the attempt is logged with
  `error: unauthorized_session`.
- The only session ids UC-03 originates are fixtures inside the development
  mock (`session-alice-1` and friends), which the company auth adapter replaces
  wholesale.
- UC-03 generates `question_id` (UUID4) — that is an interaction id, not a
  session id.

Clients cannot supply `user_id`, `naric_level`, `practice_area`,
`classification`, `authority`, `rating_state`, or a system prompt: the request
models forbid unknown fields, so any such attempt is a `422` rather than a
silently ignored value.

## 7. Status vocabulary

**[SPECIFIED]** except `FRAMINGS_EXHAUSTED` (A-14).

| `status` | `parts` | `follow_up_actions` | `retry_available` | Meaning |
|---|---|---|---|---|
| `ANSWERED` | present | all three | false | Normal answer. |
| `CLARIFICATION_NEEDED` | null | empty | false | Ambiguous; exactly one clarification question is returned and **no answer was generated**. |
| `OUT_OF_SCOPE` | null | empty | false | Not a legal-learning question; polite redirect in `message`. |
| `TIMEOUT` | null | empty | true | Exceeded the 10 s hard deadline. **No partial answer.** |
| `ERROR` | null | empty | true | Generation failed, or a follow-up was rejected as a paraphrase. |
| `FRAMINGS_EXHAUSTED` | null | empty | false | Every distinct framing for this concept has been used in this session. |

## 8. Source status / degradation vocabulary

**[ASSUMED]** (A-19). `meta.degraded` is a list of these strings; empty means a
clean path.

| Value | Meaning |
|---|---|
| `context_provider_unavailable` | Context service raised; safe defaults applied. |
| `naric_level_unavailable` | No level retrieved; default level applied. |
| `naric_level_unrecognised` | Adapter returned a level outside the closed set. |
| `practice_area_unavailable` | No practice area; general example given. |
| `authority_provider_unavailable` | Authority source raised; treated as no verified authority. |
| `topic_tag_rejected` | Tagger proposed a tag outside the vocabulary. |
| `citations_redacted` | Generated prose contained unverified citations; they were removed. |
| `question_log_unavailable` | Log write failed; record written to stderr instead. |
| `framing_registry_unavailable` | Framing history unreadable. On a follow-up this fails the request rather than risk repeating a framing. |

Framing strategies (**[ASSUMED]**, A-09): `analogy`, `worked_example`,
`contrast_near_miss`, `first_principles`, `procedural_walkthrough`,
`misconception_correction`.

## 9. Extension points

Every place behaviour UC-03 does not own attaches. All are `typing.Protocol`s in
[`uc03/contracts.py`](../uc03/contracts.py) — structural, so your class needs no
import from UC-03. A conformance suite exists for each; see
[../INTEGRATION.md](../INTEGRATION.md).

| Port | Attaches to | UC-03 depends on it for |
|---|---|---|
| `ContextProvider` | Company NARIC/context service + Legal Footprints | Explanation depth, practice-area personalisation |
| `LegalAuthorityProvider` | Approved legal authority source | The entire Authority Reference part |
| `QuestionClassifier` | Company classifier or an LLM | Routing before any generation |
| `AnswerGenerator` | Company generator or an LLM | The three prose parts only |
| `TopicTagger` | Company tagger or an LLM | A *proposal*, always validated |
| `QuestionLogger` | Company database / event log | Writing the §1 record |
| `InteractionReader` | Read path over the same store | Anchoring a follow-up to its original |
| `SessionAuthorizer` | Company authentication / session system | Identity and session ownership |
| `FramingRegistry` | Company storage | The never-repeat-a-framing rule |
| `Clock` | — | Deterministic timestamps in tests |

Non-port extension points:

- **Configuration** ([`uc03/config.py`](../uc03/config.py)) — all deadlines,
  limits, thresholds and learner-facing message text, overridable by `UC03_*`
  environment variables. Guardrail text is configuration, never request data.
- **Composition root** ([`uc03/factory.py`](../uc03/factory.py)) — the single
  place adapters are chosen.
- **Topic vocabulary** ([`uc03/domain/topics.py`](../uc03/domain/topics.py)) —
  extend the enum rather than accepting free text.
- **Framing set** ([`uc03/domain/enums.py`](../uc03/domain/enums.py)) — adding a
  framing extends how many follow-ups a concept supports before exhaustion.

## 10. What UC-03 does not do

No frontend. No production database. No rating workflow (UC-10 owns
`rating_state` transitions). No follow-up *handlers* beyond the three actions
implemented here. It does not import, assume, or name any other component of the
platform.
